# Cookie 获取与放行指引（抖音 / TikTok 系平台）

> 本文档只描述**用你自己已登录的浏览器、按平台正常访问流程取得凭据**的做法。
> **不提供、也不建议使用**任何绕过平台风控、伪造 `s_v_web_id` 签名、
> 模拟验证挑战或批量刷取凭据的方案。本项目也不包含此类代码。

## 0. 为什么需要这一步

部分平台（实测：抖音 / TikTok 系）要求浏览器验证挑战生成的 `s_v_web_id`
（上游实现见 `vendor/yt_dlp/extractor/tiktok.py`），服务端直接请求其 Web detail API
会返回 403。片语为此接通了两条官方 Cookie 通道，**都不需要修改 yt-dlp 源码**：

| 通道 | 怎么配 | 适合场景 |
|---|---|---|
| 浏览器 Cookie | 界面「设置 → Cookie 来源」选 Chrome / Edge / Firefox / Safari | 常规桌面环境 |
| `cookies.txt` | 把 Netscape 格式文件放到 `cookies/` 下，命名 `cookies.txt` | 无浏览器、断网、批量复验 |

判断当前状态最快的方式是诊断接口：

```bash
python3 cookies/cookie_doctor.py --probe
```

它会明确告诉你缺什么：没有凭据、凭据陈旧、还是被系统权限挡住读取。

> 常见情形：浏览器里明明登录着，程序却读不到。这不是缺凭据，而是操作系统的
> 隐私保护拦住了 Cookie 库读取（macOS 上表现为 `Operation not permitted`）。
> 遇到这种情况按下面路径 A 导出一次 `cookies.txt` 最省事。

## 1. 三条获取路径（按推荐度排序）

### 路径 A：浏览器扩展导出 `cookies.txt`（推荐，最省事）

1. 用 Chrome / Edge / Firefox **正常打开并浏览** `https://www.douyin.com/`，
   让站点按自身流程种下 `s_v_web_id`（**不需要登录账号**）。
2. 安装导出扩展（如 *Get cookies.txt LOCALLY*），只导出当前站点。
3. 把导出的文件放到 `cookies/cookies.txt`。
4. 确认文件是 Netscape 格式、Tab 分隔、含 `.douyin.com` 域与 `s_v_web_id`。
5. 执行体检：

   ```bash
   python3 cookies/cookie_doctor.py --probe
   ```

### 路径 B：macOS Safari + 完全磁盘访问权限

> **实测说明**：在部分 macOS 版本上，Safari 的 `Cookies.binarycookies` 已是私有 / 新格式
> （文件头 version=`0x76`，页面不以 `cook` 起头），标准解析器与
> `cookies/export_safari_cookies.py` 都可能解出 0 条。**若脚本解析为 0 条，请直接走路径 A**，
> 不要在授权上反复折腾。

1. 用 Safari 登录 / 访问过目标站点。
2. 「系统设置 → 隐私与安全性 → 完全磁盘访问权限」，勾选**你运行服务的终端或启动器**，
   完全退出并重开后再试。
3. 授权生效后运行自带导出器（仅导出目标域、不回显值、不出包）：

   ```bash
   cd <项目目录>
   python3 cookies/export_safari_cookies.py          # 写 cookies/cookies.txt
   python3 cookies/export_safari_cookies.py --dry    # 只预览
   ```

4. 脚本会解析 Safari 二进制 Cookie 库、过滤 `.douyin.com/.tiktok.com/.iesdouyin.com/.bytedance.com`
   等域，以 Netscape 格式写入 `cookies/cookies.txt`，随后用 `cookie_doctor.py --probe` 复验。
5. 若仍报 `Operation not permitted`，说明授权未对**当前进程**生效，改走路径 A。

> 本项目不会通过 `sudo`、改系统权限或其他方式强行读取浏览器数据。

### 路径 C：开发者工具手动取单个值

1. Chrome 打开目标站点 → `F12` → `Application` → `Cookies` → 对应域名。
2. 找到 `s_v_web_id`，复制其**值**。
3. 在 `cookies/cookies.txt` 里写一行（Tab 分隔，过期时间用未来的 Unix 秒）：

   ```
   # Netscape HTTP Cookie File
   .douyin.com	TRUE	/	TRUE	1799999999	s_v_web_id	<你复制的值>
   ```

4. 建议把同一域下的 `ttwid` 等一并导出，只放单个值有时仍会被判为陈旧凭据。

## 2. 安全与合规约束（内置的硬限制）

| 约束 | 实现位置 |
|---|---|
| Cookie 文件**必须位于项目目录内** | `fusion/guards.within()`，`engine_opts.cookie_file()` |
| 包外路径一律忽略，防止把本机任意文件当凭据外发 | 同上 |
| 健康自检不回显任何 Cookie 值 | `engine_opts.cookie_status()` |
| Cookie 文件不进 Git | `.gitignore` 排除 `cookies/*.txt` |
| 只处理自有或已获授权素材 | 合规要求，非技术限制 |
| 打包 / 分享前必须清空 `cookies/*.txt` | 见 §4 |

## 3. 验证与出稿

```bash
# ① 体检查文件（不回显值），可选 --probe 直接打真实链路
python3 cookies/cookie_doctor.py --probe

# ② 服务在跑时：诊断接口
curl -s -X POST http://127.0.0.1:8760/api/platform/diagnose \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://v.douyin.com/<你的链接>/"}'

# ③ 就绪后用界面右下角「旗舰版 · 一键知识稿」出稿
```

返回 `ready: true` 即可用 `/api/pipeline/start` 一键出稿。

## 4. 打包 / 分享前清理（必做）

```bash
rm -f cookies/*.txt          # 清空凭据
python3 cookies/cookie_doctor.py   # 应返回「文件不存在」
```

> 若接收方需要演示能力，请让对方在自己的机器上按本指引重新放置 Cookie，
> **绝不把含登录态的 Cookie 附在对外包里**。
